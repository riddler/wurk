# ADR-0019: Agent definitions are generated from templates and shared blocks

Status: proposed (2026-09-14)

## Context

`agents/` ships twelve agent definitions. Each is one markdown file with a
frontmatter block, symlinked by `install.rb` into `~/.claude/agents/`, and
named by the skills that spawn it (`/wurk:work`, `/wurk:mr`'s review
round, `/wurk:conductor`). Until now each file was written by hand, and
the prose that governs a subagent that may commit or run the gate - the
gate-wait discipline (short gate foreground, long gate started detached
and polled foreground, never a Monitor, the semaphore rules) and the rule
that a dispatch is relayed verbatim (the consent quote and the applicable
gate tier) - lived in `wurk-repo-worker.md` as two long sections that
nothing else could reuse. A consumer whose campaigns need extra rules
ships its own worker variant under another name (the repo-worker's own
description says so), and that consumer carries forked copies of exactly
those sections, and nothing carries an edit here across to the fork: the
discipline changed this campaign (wu-yi7.1 added the report-file step
and the kill-children-by-PID rule), and each such change is a
by-hand port for every copy. Another harness builds its agents from templates
plus shared blocks with a routing file, and wu-yi7.9 asks wurk to adopt
the same shape.

Constraints, cited rather than re-argued: ADR-0002 (wurk is consumed by
symlink; `install.rb` globs `agents/*.md`, so whatever is generated has to
keep existing at those paths under those names), ADR-0006 (a kit script is
stdlib Ruby under the envelope contract with `--dry-run` on every mutating
path; the contract test enforces it), ADR-0004 and CLAUDE.md's hard rule
(no consumer constant in a kit script or a shipped agent), and the
dogfooding hazard the campaign named: `agents/*.md` are the live
definitions, including the one this bead's worker ran under, so the first
generated output had to be the current prose byte for byte, with no
wording change to any agent's behavior.

What was actually repeated, measured against the twelve files rather than
assumed: the two repo-worker sections above exist once, in one file, and
are the text a forked variant needs. Between the other agents the shared
text is a heading (`## REMEMBER: You are a documentarian, not a critic or
consultant`, three files, with different bodies), a nested list item (the
`.claude/wurk/codebase.md` orienting rung, identical in the analyzer and
the pattern finder, differently worded in the locator because it has no
Read tool), and two single sentences in the two critics ("An unranked
finding is not a blocker; do not leave one unranked." and "Order findings
by severity, must-fix first."). None of those is a block worth a routing
entry: the heading's bodies differ, the rung is one item of a four-item
list, and a one-sentence block costs more in routing than it saves.

## Decision

**Every file in `agents/*.md` is generated. The sources are a template
per agent, a directory of shared blocks, and one routing file; a kit
script builds them and lints the routing, and the kit's own suite runs
that lint with `--check` so a drifted file turns the gate red.**

### 1. Layout

All under `agents/`, beside the generated files:

```
agents/<name>.md.in       the template: frontmatter verbatim, then prose in
                          which a line `@include <block>` stands for a block
agents/blocks/<block>.md  a shared block, spliced in verbatim; no frontmatter,
                          no includes of its own (blocks are leaves)
agents/routing.yml        blocks: {<block>: [<name>, ...]} - which agents
                          carry which block
agents/<name>.md          the generated definition, committed
```

The generated file is the template with one banner line inserted after
the frontmatter's closing fence and every include replaced by its block:

```
<!-- DO NOT EDIT: generated by build_agents.rb from <name>.md.in and blocks/ (see routing.yml); edit those and rebuild -->
```

The banner is an HTML comment in the body, not a comment inside the
frontmatter. The frontmatter is parsed by the harness that loads the
agent, and a comment there would depend on that parser tolerating one;
the body is prose, and a comment in it is inert. The banner names the
template so a reader who lands in the generated file finds the file to
edit without knowing the scheme.

Generated files stay committed at the same paths. That is what keeps
ADR-0002's install unchanged (`install.rb` still globs `agents/*.md`, and
`*.md.in`, `blocks/`, and `routing.yml` fall outside that glob) and keeps
every skill that names an agent working unchanged. A build step at
install time was rejected below.

### 2. The routing file, and why YAML

`routing.yml` is the authority on who shares what. A block's list names
every agent that carries it; the build refuses when a template includes a
block the file does not route to that agent (`unauthorized_include`),
when a listed agent's template lacks the include (`missing_include`), when
a block file has no entry (`orphan_block`), when an entry names no file
(`dangling_route`) or no template (`unknown_agent`), when a template
includes a block with no file (`dangling_include`), when a block contains
an include line (`nested_include`), when a template has no frontmatter
(`no_frontmatter`), and when an `agents/*.md` has no template
(`ungenerated_agent`). `--check` adds `stale_generated` and
`missing_generated`. Every one has a failing test.

An agent belongs on a block's list when it may do the thing the block
governs. Both blocks that exist today govern a subagent that may commit
or run the gate, so today both route to `wurk-repo-worker` alone: the
fleet scout is conductor-facing but read-only, and routing the gate
discipline to it would add prose about a protocol it cannot reach - a
behavior change, which the byte-for-byte constraint rules out for this
bead. "Shared" here means shared by routing: the blocks are the unit a
second worker-shaped agent (a consumer's forked variant, or a future
generic one) includes by adding one line to its template and one name to
this file, instead of copying two sections it will then fail to keep
current.

YAML over JSON, both stdlib (`require "yaml"` is Psych, present on the
Ruby 2.6 floor ADR-0006 names): the routing file is hand-edited and each
entry wants its reason beside it, and JSON has no comments. The manifest
stays JSON (its readers are scripts and its documentation carries the
commentary); this file's reader is a person deciding whether an agent
belongs on a list. The parse is `YAML.safe_load` and the accepted shape is
one mapping of string to list of strings; anything else is
`routing_invalid`.

### 3. The build script

`skills/wurk:kit/scripts/build_agents.rb`, in the kit rather than under
`agents/`, because it contains nothing wurk-specific: it takes `--dir`
(default `agents`), and a consumer that keeps its forked variant under
`.claude/agents/` builds it with the same script and the same lint. It
obeys the script contract: stdlib only, one envelope, exit 0/1/2,
`--dry-run` on the build (lists the writes under `commands`, writes
nothing), no shell-outs at all (pure filesystem logic, like
`campaign_state.rb`), and the contract test's banned-operation,
consumer-vocabulary, and version-floor scans apply to it unchanged. Lint
runs in every mode and refuses the build before any file is written; a
generated file is written through a sibling temp file and a rename.

`--check` is the CI verb: lint plus compare, writes nothing, exit 1 on any
finding. `test/build_agents_test.rb` runs it against the repo's own
`agents/` as one of its tests, which is how the acceptance criterion
"`--check` passes in the test suite" is met without a second gate stage,
and it asserts that the two named blocks exist and route to the repo
worker.

### 4. What changes for an editor

An agent is edited in its `.md.in`, or in a block under `blocks/`; then
`ruby skills/wurk:kit/scripts/build_agents.rb` regenerates, and the
generated file is committed alongside the source. Editing the `.md`
directly is caught by the suite as `stale_generated` on the next gate
run. A new shared block needs its file, a routing entry, and an include
in each listed template, and the lint names whichever of the three is
missing. A new agent needs a template; a hand-written `.md` beside the
templates is `ungenerated_agent`.

## Consequences

- The first generated output is the prior prose plus one banner line per
  file: twelve files, one insertion each, zero deletions, verified by diff
  before the banner was accepted. No agent's behavior changed in this
  bead; any wording change is a later, separate edit to a template or
  block.
- `install.rb` and every skill that names an agent are untouched.
  `install.rb --dry-run` against a scratch home links exactly the twelve
  generated files.
- The contract test's consumer-vocabulary scan over shipped agents now
  also covers `agents/*.md.in` and `agents/blocks/*.md`, so a hit is
  reported at the file a person edits rather than only at the generated
  copy.
- The gate grows by the new test file; the suite still runs in seconds.
- A consumer's forked worker variant can now be a template that includes
  wurk's blocks by content - but only by copying the block files into its
  own `blocks/`, because the script reads one directory. Whether a second
  block root (`--blocks DIR`) is warranted is an open question below, and
  ADR-0009's bar applies: it is added when a consumer demonstrates the
  need.
- `docs/architecture.md`, `README.md`, `.claude/wurk/codebase.md`, and
  `skills/wurk:kit/REFERENCE.md` each gain a sentence on how agents are
  edited now.

## Alternatives rejected

- **Generate at install time and commit only the sources.** Rejected:
  `install.rb` symlinks, it does not build (ADR-0002), and a generated
  file that exists only under `~/.claude` is invisible to the contract
  test's agent scan, to `git diff` review, and to a consumer reading the
  repo. Committing the output keeps the review surface where it was.
- **The script under `agents/`.** Rejected: it would be the one Ruby file
  outside `scripts/`, outside the contract test's globs, and unusable by
  a consumer building its own variant. Nothing in it is wurk-specific.
- **JSON routing.** Rejected in section 2: the file is hand-edited and
  the reason an agent carries a block belongs beside the entry.
- **A banner inside the frontmatter.** Rejected in section 1: it would
  depend on the harness's frontmatter parser accepting a comment, which is
  not documented, for no gain over an inert body comment.
- **Extracting every repeated fragment.** Rejected in the context section:
  the fragments shared between the research agents and the critics are a
  heading, a nested list item, and two sentences. Blocks that small make
  the routing file longer than the text it governs.
- **Routing the two blocks to the fleet scout so that "conductor-facing
  agents" share them today.** Rejected in section 2: the scout never
  commits or runs a gate, so the prose would be a behavior change with
  nothing to govern, and this bead is bounded to a byte-for-byte refactor.

## Open questions

- Whether the script should take a second block root so a consumer's
  variant includes wurk's blocks by reference rather than by copy. Not
  decided; it waits for the consumer that needs it.
- Whether a parameterized include (a block with a slot, so the critics'
  near-identical severity sections could become one block) is worth its
  complexity. The two sections differ by five words today; the honest
  answer is to reword one of them in a later bead and then share the
  block, not to add substitution to the build.
