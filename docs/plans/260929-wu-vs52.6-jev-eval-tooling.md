# Jev eval tooling Implementation Plan

## Overview

Build the evaluation tooling a Jev call site must pass before it may move
from `shadow` to `on`: a labelled corpus per site, a terminal labeller, a
Wilson-bound threshold sweep, a read-only shadow-to-on gate, and a small
per-site fixture set that runs on demand and whenever the model id changes.

Two pieces, following the `typesafe` lib-plus-CLI split:

- `skills/wurk:kit/scripts/lib/typesafe_eval.rb` - `TypesafeEval`, the
  library: the Wilson bound, answer interpretation, the sweep, redaction,
  the corpus format, the eval run, the threshold store, the on-gate
  predicate and the fixture runner.
- `skills/wurk:kit/scripts/typesafe_eval.rb` - the CLI over it:
  `corpus`, `label`, `run`, `sweep`, `gate`, `fixtures run`,
  `fixtures check`.

Every model call goes through `Typesafe.judge` in `lib/typesafe.rb`; this
bead adds no HTTP path, no config key, no schedule, and never writes a mode
into any config. `lib/typesafe.rb` itself is not changed.

Bead: wu-vs52.6 (epic wu-vs52). The epic's 2026-09-29 notes bind and win
over the bead description; where the description predates the landed
client (wu-vs52.1), the landed contract wins - in particular thresholds are
keyed by `Typesafe.threshold_key` (`<site>:<qset id>@<version>:<pinned
model>`), and the description's "nightly" fixture run and "eval share of
the local budget" are replaced by an on-demand command and the client's
existing budget (see What We're NOT Doing).

## Current State Analysis

- `lib/typesafe.rb` (landed, wu-vs52.1) exposes `Typesafe.judge(config:,
  input:, site:, dry_run:, now:, http_class:)` returning a `Result`
  (`outcome`, `answers`, `served_model`, `usage`, `cost_usd`,
  `threshold_key`, ...), `Typesafe.record_outcome`, `Typesafe.site_mode`
  and `Typesafe.threshold_key(site:, question_set:, model:)`
  (`lib/typesafe.rb:198-210`). The pre-call order is mode, input, privacy,
  budget, local rate, key (`:261-320`).
- A call with `site: nil` is a `probe`: it skips site gating (so a dark
  site can still be evaluated) but still runs input, privacy, budget,
  rate and key checks, and writes a ledger line and a decision line with
  `site: null, mode: "probe"` (`:198-199`). `threshold_key` is
  only filled when a site is passed (`:278-281`), so the eval computes the
  key itself with `Typesafe.threshold_key`.
- The client does NOT distinguish `on` from `shadow`: both call. The
  existing test `test_source_restricted_refuses_shadow_and_on_alike`
  (`test/typesafe_test.rb:419`) drives an `on` site through a live-shaped
  call, so making the client refuse `on` would change tested behavior; this
  plan leaves the client alone and puts the gate in the eval tool.
- Decision lines (`decisions-YYYY-MM.jsonl` in `typesafe.state_dir`) carry
  `kind: "decision"`, `ts`, `call_id`, `site`, `mode`, `question_set`,
  `threshold_key`, `model`, `served_model`, `outcome`, `answers`; the
  caller's line is `kind: "outcome"` with `call_id`, `site`, `action`,
  `decision`, `agreement` (`agree|disagree|n/a|null`)
  (`lib/typesafe.rb:338-362`, `:512-536`). Answers are the provider's
  objects: choice `{type, choice, probabilities, confidence}`, noul
  `{type, noul}`, score `{type, score, legend, probabilities, confidence}`
  (provider API docs, `https://docs.typesafe.ai/api.md`, read this
  session; no call made).
- `typesafe.restricted_sources` is a deny-list of source labels checked by
  `judge` in every mode (`:282-285`). The machine config section has no
  eval keys and none are needed (`lib/user_config.rb:50-58`,
  `docs/machine-config.md` `## typesafe`).
- Test support: `test/support/fake_http.rb` (scripted `Net::HTTP.start`
  stand-in plus a process-wide lock on the real one),
  `test/support/home_guard.rb` (tmp HOME for the whole process),
  `test/support/user_config_helper.rb` (`in_tmp_home`,
  `write_raw_user_config`). The typesafe tests pin `XDG_STATE_HOME` to a
  tmpdir themselves (`test/typesafe_test.rb:253-276`) and sweep every
  output and file for a sentinel key.
- The closest precedent for scoring against a labelled corpus is
  `critic_eval.rb` (REFERENCE.md `## critic_eval.rb`): deterministic,
  a ratio with no denominator is null never 1.0, an incomplete evaluation
  blocks. Its fixture corpus lives under `test/fixtures/critic_eval/`.
- Arithmetic fact that shapes the tests: with z = 1.96 and every routed
  case correct, the Wilson lower bound is `n / (n + z^2)`, which first
  reaches 0.90 at n = 35 (34 -> 0.898482, 35 -> 0.901096). So with the
  default bar, the ">= 10 routed" rule can never be the deciding rule on
  its own; the sweep function takes the bar as a parameter so a test can
  prove the 10-case rule independently.

## Desired End State

- `typesafe_eval.rb corpus build` turns read-only source files into one
  corpus JSON file per site and question set, with self-stated labels
  redacted, refusing any restricted source before reading it.
- `typesafe_eval.rb label` walks unlabelled cases on a terminal (prompts
  on stderr, answers on stdin, one envelope on stdout) and saves each
  label as it is given.
- `typesafe_eval.rb run` sends every labelled case through `Typesafe.judge`
  (probe calls, the client's own budget) and writes a run file whose last
  line says whether the run is complete.
- `typesafe_eval.rb sweep --run FILE` computes, per label, the smallest
  confidence threshold in 0.05..0.95 whose Wilson 95% lower bound on
  precision is >= 0.90 with >= 10 routed cases, else `n/a`; `--apply`
  stores the result under the run's threshold key, and refuses a partial
  run.
- `typesafe_eval.rb gate --site S --question-set ID@VER` is read-only and
  exits 0 only when the site's current threshold key has an enabled
  threshold AND the shadow evidence bar (>= 3 days, >= 35 accepted
  judgments at that bound, and a Wilson lower bound >= 0.90 on shadow
  agreement at that bound) is met; otherwise exit 1 with a block. It
  never writes anything. **The gate is advisory:** nothing in the kit
  can stop a person from editing a site's mode, and the unchanged client
  treats `on` like `shadow`. "The on-mode switch refuses" means exactly
  this: `gate` exits 1 for such a site, and the REFERENCE.md caller rule
  says an `on` site acts on Jev only through `threshold_for`, which
  returns nil (act as `shadow`) for a key with no enabled threshold.
- `typesafe_eval.rb fixtures run --fixtures FILE` runs a site's fixture
  set on demand; `fixtures check --fixtures FILE...` runs each set only
  when the model id changed since that set's last run. Failure is exit 1
  plus `blocked`, nothing else.
- Verified by `/usr/bin/ruby skills/wurk:kit/scripts/test/run.rb` green,
  including `typesafe_eval_test.rb` and `typesafe_eval_cli_test.rb`, and
  the acceptance map in Testing Strategy.

### Definitions this plan fixes

- **Interpretation of an answer** (`TypesafeEval.interpret(answer)` ->
  `[predicted_label, confidence]` or nil):
  choice (answer `{type: "choice", choice, probabilities, confidence}`)
  -> `[answer["choice"], answer["confidence"]]`;
  noul (answer `{type: "noul", noul}`, a probability of yes) ->
  `p = answer["noul"]`, `[p >= 0.5 ? "true" : "false", max(p, 1 - p)]`.
  Nil when the answer's `type` is not `choice` or `noul` (a `score`
  question is out of scope for this bead), a field is missing, the choice
  is not one of the question's labels, or the confidence (or `noul`) is
  not a number in 0..1. A nil interpretation is an `unreadable_answer`.
  The answer shapes are the provider's documented ones
  (`https://docs.typesafe.ai/api.md`, "Answer types").
- **Labels of a question**: choice -> the keys of its `criteria` object
  (a choice question whose `criteria` is not a non-empty object is
  refused as `question_set_invalid`); noul -> `["true", "false"]`. A
  `score` question is refused as `question_set_invalid` (see What We're
  NOT Doing).
- **Routed**: at threshold t, a judged case is routed to label L when its
  interpretation is `[L, c]` with `c >= t`. Thresholds are `i / 20.0` for
  i in 1..19 (0.05..0.95, step 0.05), computed from integers so there is
  no accumulated float drift.
- **Wilson lower bound** (z = 1.96, two-sided 95%): for k correct of n
  routed, `p = k/n`,
  `lb = (p + z^2/(2n) - z*sqrt(p(1-p)/n + z^2/(4n^2))) / (1 + z^2/n)`;
  n = 0 -> nil (no denominator is never a pass).
- **Sweep result per label**: the smallest t with `n >= 10` and
  `lb >= 0.90` -> `{threshold: t, routed: n, correct: k, precision: k/n,
  lower_bound: lb}`; otherwise `{threshold: nil, reason:
  "too_few_routed" | "below_bound", best: <the t with the highest lb among
  t with n >= 10, or nil>}`. `too_few_routed` when no t has n >= 10;
  `below_bound` when some t has n >= 10 but none clears the bound. A label
  with `threshold: nil` is `n/a` and can never turn on.
- **A partial run** is any run file for which one of these holds; a
  partial run is never applied:
  1. no `run_end` line (the process died or was killed);
  2. `run_end.complete` is false - written when the runner stopped early
     for any reason: `Interrupt` (Ctrl-C), an exception, or the first case
     whose outcome was not `ok`;
  3. any labelled case in the corpus has no `judgment` line, or its
     judgment's `outcome` is not `ok` (a mid-run `budget_exhausted`,
     `rate_limited`, `timeout`, `model_mismatch`, `source_restricted`, any
     member of the closed set other than `ok`), or its answer is an
     `unreadable_answer`;
  4. the run's `corpus_digest` differs from the corpus file's current
     digest (labels or cases changed after the run);
  5. the run's `threshold_key` differs from the key computed now from the
     corpus's site and question set and the machine's pinned model.
- **An enabled threshold** for key K: the threshold store holds an entry
  for K (only ever written from a complete run) with at least one label
  whose `threshold` is a number. Those labels are the enabled labels.
- **An accepted judgment** for key K and site S: a `kind: "decision"` line
  with `site == S`, `mode == "shadow"`, `threshold_key == K`,
  `outcome == "ok"`, `ts >=` the store entry's `applied_at`, whose answer
  for the entry's question interprets as `[L, c]` with L an enabled label
  and `c >= threshold[L]` (it would have been routed at the stored bound),
  AND whose latest `kind: "outcome"` line (by `ts`) for the same
  `call_id` has `agreement == "agree"`. A **disagreed judgment** is the
  same with `agreement == "disagree"`. A routed decision whose latest
  outcome line is `n/a`, null, or absent counts as neither.
- **The shadow span**: from the `ts` of the earliest decision line that
  meets every accepted-judgment condition except agreement (the first
  routed shadow decision at the bound) to `now`.
- **The evidence bar**: span >= 259200 s (3 days), accepted >= 35, AND
  `wilson_lower_bound(accepted, accepted + disagreed) >= 0.90`. With no
  disagreements the bound is `a / (a + z^2)`, which first clears 0.90 at
  a = 35 - the same arithmetic the eval uses - so 35 is the floor and
  every disagreement raises the number of agreements needed. Disagreements
  are therefore not advisory: they count against the bound.
- **Model id change** (fixtures): for a fixture set whose last run is
  recorded in the fixture state file, a change is (a) the machine's pinned
  `typesafe.model` differs from the recorded model, or (b) any decision
  line with `ts` after the set's recorded `ran_at` has a non-null
  `served_model` different from the recorded model, or outcome
  `model_mismatch`. `ran_at` is stamped AFTER the set's last fixture call
  returns, so the run's own decision lines never re-trigger it. Scan (b)
  is deliberately machine-wide - every site's and every probe's decision
  lines count - because the served model is a property of the provider
  and the machine's pinned id, not of one site. A set with no recorded run
  counts as changed (`no_baseline`).

## What We're NOT Doing

- No change to `lib/typesafe.rb`, `typesafe.rb`, or their tests. The
  client keeps treating `on` like `shadow`; the gate is a separate
  read-only check, and REFERENCE.md gains a caller rule that an `on` site
  acts on Jev only for an enabled label at or above its stored threshold
  (`TypesafeEval.threshold_for`), which can only restrict.
- Nothing switches a site to `shadow` or `on`, and nothing shipped writes
  any key of `~/.claude/wurk.local.json`. The gate reports; a person edits
  the machine config.
- No new `user_config.rb` key and no `docs/machine-config.md` change. The
  eval spends under the client's existing `typesafe.budget.monthly_usd`
  and `per_minute`; a run that the budget refuses mid-way is partial and
  is not applied. (The description's "eval share of the local budget" is
  not built; see Open Questions.)
- No schedule of any kind: no launchd, cron or Monitor entry, and no
  "nightly" run. `fixtures check` is a command an operator or a campaign
  invokes; the description's "nightly" becomes "on demand, and whenever a
  check finds a model id change".
- No notifier. A fixture failure is exit 1 and a `blocked` entry.
- No site-specific question sets, corpora or fixture sets. Site beads
  (wu-vs52.2 - wu-vs52.5) ship their own; this bead ships the format, the
  tooling and SYNTHETIC examples under `test/fixtures/typesafe_eval/`.
- No reading of any other repo's files into a fixture or corpus; committed
  fixtures are synthetic text written for this bead.
- No live Jev call in any test or automated criterion. Tests use
  `FakeHTTP`; the plan's only live call is an optional operator item.
- No edits to the conductor skill, `report_check.rb`, any site code, or
  another bead's REFERENCE.md section.
- No `score` questions. The sweep, the run and the fixtures handle
  `choice` and `noul` only; a question set whose evaluated question is a
  `score` is refused (`question_set_invalid`). Routing a probability-
  weighted level is a different rule, and no site bead in the epic asks
  for one yet. No multi-question sweep either: one corpus evaluates one
  question id.
- No resume of a partial run. The first non-`ok` outcome stops a run and
  the whole corpus is re-run next time. Deliberate: a resumed run would
  mix judgments from different times (and possibly a different served
  model) under one threshold, and the cost of a full re-run is small (the
  client's own measured probe cost is about 1.2e-05 USD per call).

## Implementation Approach

Bottom-up, each phase green on its own:

1. Pure math first (no IO): Wilson bound, interpretation, the sweep, the
   threshold grid. The acceptance tests against hand-computed bounds land
   here.
2. The corpus: format, digest, redaction, the builder (read-only sources,
   restricted-source refusal) and the terminal labeller, with the CLI
   skeleton and the new REFERENCE.md section.
3. The eval run through `Typesafe.judge`, the run file, the partial-run
   rules, `sweep --apply` and the threshold store.
4. The on-gate predicate and command, and the fixture runner with its
   model-change trigger.

The library never prints, never exits; the CLI turns results into one
envelope. Every file the tool writes lives under
`<typesafe.state_dir>/eval/` (run files, the threshold store, the fixture
state) or is a corpus path the operator names; nothing is written next to
a source.

## Phase 1: Wilson bound, interpretation and the sweep

### Overview

Pure functions in `lib/typesafe_eval.rb` and their tests. No files, no
config, no network.

### Changes Required:

#### 1. The library core
**File**: `skills/wurk:kit/scripts/lib/typesafe_eval.rb` (new)
**Changes**:

```ruby
# frozen_string_literal: true

module TypesafeEval
  Z = 1.96
  MIN_ROUTED = 10
  MIN_LOWER_BOUND = 0.90
  THRESHOLDS = (1..19).map { |i| i / 20.0 }.freeze   # 0.05..0.95

  def self.wilson_lower_bound(correct, routed, z: Z)   # -> Float or nil (routed 0)
  def self.interpret(answer)                            # -> [label, confidence] or nil
  def self.labels_for(question)                         # choice/noul label list
  # judged: [{label: gold, predicted:, confidence:}], one per case
  def self.sweep(judged, labels:, min_routed: MIN_ROUTED,
                 min_lower_bound: MIN_LOWER_BOUND, z: Z) # -> {label => result}
end
```

- `sweep` returns, per label in `labels` (every label appears, even one no
  case predicts), the result shape in "Definitions this plan fixes".
  Numbers in the result are rounded to 6 places for output only; the
  comparison `lb >= min_lower_bound` uses the unrounded value.
- Arguments validated: `correct` and `routed` non-negative integers with
  `correct <= routed`, else `ArgumentError`.
- Ruby 2.6 only: no `filter_map`, `tally`, `except`, numbered params.
- `test/load_graph_test.rb` runs EVERY non-test `.rb` under `scripts/`,
  `lib/` included, as `ruby -w <file> --help` through a symlink and fails
  on any stderr line containing "warning"; and it checks the require
  graph for cycles. So the library must load warning-free under `-w`
  (no unused locals, no shadowed block variables, no redefined
  constants), and nothing it requires may require it back.

## Phase 2: The corpus builder, redaction and the terminal labeller

### Overview

The corpus format and its digest, self-stated-label redaction, a builder
that reads sources read-only and refuses restricted ones, a terminal
labeller testable with `StringIO`, the CLI skeleton, and the new
REFERENCE.md section.

### Changes Required:

#### 1. Corpus, redaction, builder, labeller
**File**: `skills/wurk:kit/scripts/lib/typesafe_eval.rb`
**Changes**:

- **Question-set file** (input to `corpus build`, `run` and fixtures):
  `{"question_set": {"id", "version"}, "question": "<qid>", "questions":
  {"<qid>": {type, instructions, criteria}}}`. Validated by calling the
  public `Typesafe.validate_input({"state" => "", "questions" =>
  questions, "question_set" => question_set}, site: site)` with a
  placeholder state (its question rules are private, and a site call
  requires `question_set`), then `labels_for(questions[question])`; any
  failure, or a `question` not in `questions`, is `question_set_invalid`
  with the field name only. `question` names the one question this corpus
  evaluates.
- **Corpus file** (one JSON object, written with a trailing newline):

  ```json
  {"format": 1, "site": "<site>", "question_set": {"id": "...", "version": 1},
   "question": "<qid>", "questions": {"<qid>": {...}}, "labels": ["a", "b"],
   "redaction": {"keys": ["priority"], "labels": ["a", "b"]},
   "cases": [{"id": "...", "source": "<label>", "state": "...",
              "redactions": 1, "label": null}]}
  ```

  `TypesafeEval.corpus_digest(corpus)` = SHA-256 (stdlib `digest`) of
  `JSON.generate` of `[question_set, question, questions, labels, cases
  mapped to [id, source, state, label]]` - any case, label or question
  text change is a new digest.
- **Redaction** (`TypesafeEval.redact(text, keys:, labels:)` -> `[text,
  count]`, applied to every string inside a state, recursively through
  objects and arrays):
  - R1 key-value: for each redact key K, `Regexp.escape`d,
    `/\b(K)\s*[:=]\s*[^,;|\n]*/i` -> `: [redacted]` (the key is kept,
    the value up to the next `,` `;` `|` or end of line is replaced).
    "Priority: LOW" -> "Priority: [redacted]".
  - R2 tagged label: for each label value L, `Regexp.escape`d and matched
    case-insensitively as a whole token, the WHOLE tag is replaced:
    `[L]`, `(L)`, `{L}` and `#L` -> `[redacted]`; `label: L` and
    `label=L` -> `label: [redacted]`. "tagged [high] here" -> "tagged
    [redacted] here"; "#high" -> "[redacted]".
  - Each replacement adds 1 to the count.
  - Bare prose occurrences of a label word are NOT redacted (they are the
    content being judged). Keys come from `--redact-key` (repeatable); the
    label list comes from the question set. Both are recorded in the
    corpus's `redaction` field.
- **Builder** (`TypesafeEval.build_corpus(config:, question_set_file:,
  site:, sources:, redact_keys:)` -> corpus hash or a refusal):
  - A source is `{kind: "dir", path:, glob:, source:}` (one case per
    matching regular file, id = path relative to the dir, state = file
    text) or `{kind: "jsonl", path:, source:}` (one case per line, each
    `{id, state}` with state a string, object or array).
  - `source` labels are REQUIRED for every source. Any label listed in
    `config.typesafe_restricted_sources` refuses the whole build with
    `source_restricted` BEFORE any source file is opened, and nothing is
    written.
  - Sources are only read (`Dir.glob`, `File.read`, `File.foreach`); the
    output path may not equal a source file or lie inside a source dir
    (refused as `output_inside_source`).

## Phase 3: The eval run, partial-run rules, sweep apply and the threshold store

### Overview

Send every labelled case through `Typesafe.judge`, record the run, and
apply a sweep only from a complete run.

### Changes Required:

#### 1. Run, sweep, store
**File**: `skills/wurk:kit/scripts/lib/typesafe_eval.rb`
**Changes**:

- `TypesafeEval.run(config:, corpus_path:, now: -> { Time.now.utc },
  http_class: Net::HTTP, sleeper: ->(s) { sleep(s) }, dry_run: false)`:
  - Loads the corpus; the judged set is the cases with a non-nil label
    (unlabelled cases are never sent). Zero labelled cases -> refusal
    `nothing_labelled`.
  - Pre-flight, before any call: every case's `source` is checked against
    `config.typesafe_restricted_sources` -> refusal `source_restricted`
    with zero calls (the client would refuse each one anyway; checking
    first spends nothing). The threshold key is computed with
    `Typesafe.threshold_key(site: corpus.site, question_set:,
    model: config.typesafe_model)`.
  - Run file `<state_dir>/eval/runs/<run_id>.jsonl` (run id =
    `YYYYMMDDTHHMMSSZ-<hex4>`), dir mode 700, file mode 600, one line per
    write: `{kind: "run_start", run_id, site, question_set, question,
    threshold_key, corpus_digest, cases}`; then per case `{kind:
    "judgment", case_id, call_id, outcome, served_model, predicted,
    confidence, gold}` (no state text, no question text); then
    `{kind: "run_end", complete, stop_reason, ok_count}`.
  - `now` is a clock lambda so the rate wait can be tested; each case
    passes `now: now.call` (a `Time`) to `Typesafe.judge`.
  - Each case: `Typesafe.judge(config:, input: {state, questions: {q =>
    ...}, question_set:, source:}, site: nil, now: now.call, http_class:)` - a probe
    call, so a site that is still `off` can be evaluated, and the
    client's own budget, rate, privacy, key and log rules all apply.
  - `rate_limited_local` (a pre-call refusal; nothing was sent) calls
    `sleeper.call(Typesafe::RATE_WINDOW_S)` (60 s, the client's own
    window) and retries that case, at most 3 waits per case, then stops
    with `stop_reason: "rate_limited_local"`. The judgment line for a
    retried case is written only for its final attempt. No other outcome is
    retried: the first non-`ok` outcome, or an `ok` whose answer does not
    interpret (`unreadable_answer`), writes its judgment line and stops
    the run with `run_end.complete: false` and `stop_reason` = that
    outcome.
  - `Interrupt` or any `StandardError` inside the loop writes `run_end`
    with `complete: false`, `stop_reason: "interrupted"` or the exception
    class, then re-raises `Interrupt` (the CLI turns it into a block) or
    returns the refusal for an exception.
  - `dry_run`: `Typesafe.judge(..., dry_run: true)` for the first case
    only (to surface a budget, price or key refusal), reports how many
    calls a live run would make, writes nothing.
- `TypesafeEval.partial_reasons(run_lines, corpus:, config:)` -> `[]` for a
  complete run, else the list of reasons from "A partial run" (names:
  `no_run_end`, `stopped_early`, `case_missing`, `case_not_ok`,
  `corpus_changed`, `key_changed`).
- `TypesafeEval.sweep_run(run_lines, corpus:)` -> the Phase 1 sweep over
  the run's judgments with the corpus's labels.
- Threshold store `<state_dir>/eval/thresholds.json`: `{format: 1,
  keys: {threshold_key => {site, question_set, question, labels: {label =>
  result}, run_id, corpus_digest, applied_at}}}`. `TypesafeEval.apply(...)`
  refuses with `partial_run` (listing the reasons) when `partial_reasons`
  is non-empty and writes nothing; otherwise replaces the entry for that
  key (tmp file then rename). Entries for other keys are untouched.
- `TypesafeEval.threshold_for(config:, threshold_key:, label:)` -> the
  stored number or nil. This is the read a site uses in `on` mode.

## Open Questions

Each item is DECIDED in this plan (the default below is what gets built);
the item records what a human may want to overrule, and nothing blocks
implementation.

1. **Eval budget share.** Decided: no share and no new config key; eval
   and fixture calls spend under the client's existing monthly cap and
   per-minute rate, and a run the budget stops is partial and not
   applied. Overrule by adding a `typesafe.budget` key (with its
   `docs/machine-config.md` change in the same commit) in a later bead.
2. **Nightly fixtures.** Decided: `fixtures check` is on demand only; the
   campaign consent forbids installing a schedule. Deferred: whether the
   conductor skill runs `fixtures check` at campaign start belongs to a
   later conductor bead, not this one (this bead may not touch the
   conductor skill).
3. **Eval calls as probes.** Decided: eval and fixture calls are probe
   calls (`site: nil`), so a dark site can be evaluated, the client's
   budget, privacy, key and log rules still apply, and the gate's shadow
   count never sees them (it counts `mode: "shadow"` only). Deferred: an
   `eval` marker on decision lines would need a client change and belongs
   with any later client bead.
4. **Disagreements at the bound.** Decided: they count against the gate's
   Wilson bound (see "The evidence bar"), so 35 agreements suffice only
   with zero disagreements. Overrule only by changing that definition
   here and in REFERENCE.md together.
5. **Shadow span start.** Decided: the first routed shadow decision at the
   bound after the threshold was applied (stricter than the apply time
   when a site sits in `shadow` without traffic).
6. **Where site fixture and question-set files live.** Decided: the site
   bead chooses and passes paths; this bead ships only synthetic test
   fixtures. Deferred to wu-vs52.2, the first site bead, to set a
   convention if it wants one.
7. **Redaction coverage.** Decided: R1 (`--redact-key` key-value) and R2
   (tagged label tokens) only; bare prose label words are kept as
   content. A source whose self-stated labels take another shape needs a
   new rule, added by the site bead that meets it, with a test.
8. **Client-side `on` refusal.** Decided: the client is unchanged; the
   `on` rule lives in the caller contract plus `threshold_for`, and the
   gate is advisory. Deferred: making `Typesafe.judge` itself refuse
   `on` for a key with no enabled threshold would change existing
   `on`-mode test fixtures and belongs to a later client bead.
9. **Score questions.** Decided: out of scope (refused as
   `question_set_invalid`). Deferred to the first site bead that needs a
   `score` question, which would define its routing rule.
10. **No resume of a partial run.** Decided: a stopped run is re-run in
    full (see What We're NOT Doing).
