# TypeSafe Jev client for the kit Implementation Plan

## Overview

Add a stdlib-only client for TypeSafe's System One API (the Jev model:
typed judgments with probabilities, never free text) to the kit, so later
call sites (the four site beads under the same epic) can ask Jev a
question in shadow mode without each one re-deriving the transport,
failure handling, budget, privacy and logging rules.

Three pieces:

- `skills/wurk:kit/scripts/lib/typesafe.rb` - the library every call site
  requires: site gating, privacy switch, key handling, local budget and
  rate limit, one HTTP attempt under a hard deadline, a closed outcome set,
  the decision log and the caller's outcome line.
- `skills/wurk:kit/scripts/typesafe.rb` - the CLI over that library
  (`call`, `outcome`), for smoke tests, operators and shell callers.
- A `typesafe` section in the machine config (`lib/user_config.rb`,
  documented in a new `## typesafe` section of `docs/machine-config.md`).

The feature SHIPS DARK: every site defaults to mode `off` in code and in
the docs, and a machine with no `typesafe.budget.monthly_usd` cannot make a
live call at all.

Bead: wu-vs52.1 (epic wu-vs52). The bead's 2026-09-29 notes and the epic's
2026-09-29 notes are binding and win over the bead description wherever
they disagree; in particular the description's "Retry 429 and 529 with
exponential backoff" paragraph is superseded - this client makes exactly
one HTTP attempt per call and never retries.

## Current State Analysis

- No kit script talks HTTP today. Every external effect goes through
  `lib/sh.rb` (ADR-0006), and `judge_test.rb:419` asserts `judge.rb` itself
  never uses `Net::HTTP` - a per-script rule for the judge, not a kit-wide
  ban. `contract_test.rb`'s rules scan for `system(`, backticks, process
  creation, banned calls, consumer vocabulary, forge vocabulary and
  post-2.6 methods (`contract_test.rb:115-143`, `:310-313`, `:345-358`);
  none of them forbids `net/http`, `timeout`, `securerandom` or `openssl`,
  all stdlib on system Ruby 2.6.10. The client needs no shell-out.
- System Ruby 2.6.10 has `Net::HTTP#write_timeout=` and
  `Net::WriteTimeout` (checked with `/usr/bin/ruby` this session), so all
  three per-socket timeouts are available on the floor.
- Bundled minitest is 5.11.3 (`/usr/bin/ruby`), which the gate uses.
- `lib/user_config.rb` is the machine-config reader. HOME-anchored only

  passed through when sent.

## Desired End State

- `ruby skills/wurk:kit/scripts/typesafe.rb call --site NAME --input
  FILE` (or `--input -` for stdin) returns one envelope: `ok: true` with
  `data.outcome = "ok"` and the answers, or `ok: false` with exactly one
  `blocked` entry whose `code` is one outcome from the closed set below and
  `data.outcome` equal to it. A caller routes on `data.outcome` alone.
- Exactly one HTTP attempt per live call, through `Net::HTTP.start` (a new
  connection per call, closed when the block exits, never pooled), bounded
  by the site's `deadline_ms` as open/read/write timeouts plus an overall
  `Timeout.timeout` guard.
- Every pre-call refusal happens before any request is built on the wire
  and before the key file is touched: every check that does not need
  the key (mode, input, privacy, budget, local rate) runs first.
- The key file's contents appear in no envelope, log line, exception
  message, test output or fixture; `--dry-run` shows the request with
  `Authorization: Bearer [REDACTED]`.
- A decision log line per call (except `site_off`) and an optional caller
  outcome line per call, neither carrying state or question text unless
  `typesafe.log_state` is true.
- Every site defaults to `off`.
- Verified by: `/usr/bin/ruby skills/wurk:kit/scripts/test/run.rb` green,
  including the new `typesafe_test.rb` and `typesafe_cli_test.rb`, and the
  acceptance-criteria map at the end of Testing Strategy.

### The closed outcome set

| code | when | request sent? | `needs` |
|---|---|---|---|
| `ok` | 200, decodable, served model == pinned model | yes | - (not blocked) |
| `site_off` | site mode is `off` (the default) | no | `none` |
| `source_restricted` | input `source` is in `typesafe.restricted_sources` | no | `none` |
| `input_invalid` | input JSON unreadable or wrong shape | no | `human` |
| `key_missing` | key file absent, unreadable, or blank | no | `human` |
| `budget_exhausted` | reason `budget_unset`, `price_unknown`, `spend_unmeasurable`, or `cap_reached` | no | `human` |
| `rate_limited_local` | at or over `per_minute` attempts in the trailing 60s | no | `none` |
| `unauthorized` | 401 or 403 | yes | `human` |
| `rejected` | 422 | yes | `human` |
| `rate_limited` | 429; `retry_after` passed through when sent | yes | `none` |
| `overloaded` | 529 | yes | `none` |
| `other_status` | any other non-200 status | yes | `none` |
| `timeout` | open, read or write timeout, or the overall deadline | yes | `none` |
| `transport` | socket, DNS, TLS, connection refused/reset, EOF | yes | `none` |
| `undecodable` | 200 but body is not JSON, or `answers` missing / not an object | yes | `none` |
| `model_mismatch` | 200 but response `model` != pinned model (or absent); answers discarded | yes | `human` |

`model_mismatch` is an addition to the closed set the binding notes list:
thresholds are keyed by pinned model id, so an answer from a different
model cannot be read against them. `input_invalid` and `source_restricted`
are refusals the notes imply (input checking, the epic's privacy gate)
rather than name. `needs: "none"` marks a refusal with nothing for a
person to fix right now - the caller falls back and moves on (see Open
Questions for whether a new `needs` value is acceptable).

### The fallback rule (stated in REFERENCE.md for every site)

Any outcome other than `ok` means: do exactly what the site did before
Jev existed, and log it. A non-`ok` outcome is never read as a "no", a low
score, or any other answer.

## What We're NOT Doing

- No retries, no backoff, no connection reuse. The description's retry
  paragraph is superseded by the binding notes.
- No call sites. Wiring Jev into the conductor, the review round, dedupe
  or model tier is wu-vs52.2 - wu-vs52.5.
- No threshold storage, sweep, labelled corpus, labeller or per-site
  fixture runner. This bead exposes the threshold KEY
  (`Typesafe.threshold_key`) and documents its shape; storing and sweeping
  thresholds is wu-vs52.6.
- No nightly or model-id-change fixture runs (binding note 8) - wu-vs52.6.
- No price shipped in the kit. Pricing reuses `metrics.prices`, which the
  operator fills.
- No `--config` flag and no config-path environment variable: a campaign
  that wants a different config sets `HOME`, which `UserConfig` already
  anchors on. Zero new mechanism.
- No real network call from any test, and no smoke call against the live
  API as part of this plan's automated criteria.
- No edits to `lib/manifest.rb`, to `contract_test.rb`'s banned-call
  table, or to `test/support/home_guard.rb`. The kit REFERENCE.md gets one
  new self-contained section; `docs/machine-config.md` gets one new
  `## typesafe` section. The existing paragraph in REFERENCE.md that
  enumerates the machine-config sections is left alone (it points at
  `docs/machine-config.md`, which carries the new section).
- No `question_set` value in the per-site config. The dispatch sketched
  one; this plan keeps the question set (text and version) in the caller's
  code and input, because a config value would split a version from the
  text it versions. See Open Questions.
- No `status` subcommand reporting month spend. The ledger is a plain
  JSONL file an operator can read; a status view can come with the site
  beads if they need one.
- No locking around the ledger. Concurrent callers may both pass a budget
  check that only one of them should have; the overshoot is bounded by one
  call's cost per concurrent caller and is documented.

## Implementation Approach

Build bottom-up so each phase is green on its own:

1. Config first: the `typesafe` section, its accessors and validation, and
   its doc section. Nothing consumes it yet, but its tests exercise every
   accessor and every block/warn rule, so the phase is complete.
2. The HTTP core as a pure client object that takes a key string, a model,
   a deadline and an `http_class` seam (default `Net::HTTP`). Tests replace
   the seam with a fake that mimics `Net::HTTP.start` and returns real
   `Net::HTTPResponse` objects, proving outcome mapping, the one-attempt
   rule, timeouts and redaction without a socket.
3. The policy layer that call sites use: site gating, privacy switch, key
   file handling, budget ledger, local rate limit, price rule, decision
   log and outcome line - `Typesafe.judge` and `Typesafe.record_outcome`.
4. The CLI and the REFERENCE.md contract section.

The library never prints, never exits, and never raises past its public
entry points for anything in the closed set: it returns a `Result`. The
CLI turns a `Result` into an envelope.

## Phase 2: The HTTP client core

### Overview

`Typesafe::Client` in `lib/typesafe.rb`: build the request, make exactly
one attempt under a hard deadline, map every result into the closed
outcome set, and redact. No config, no files, no budget - those are
Phase 3. Tests drive it through a fake `Net::HTTP`.

### Changes Required:

#### 1. The client
**File**: `skills/wurk:kit/scripts/lib/typesafe.rb` (new)
**Changes**:

```ruby
# frozen_string_literal: true

require "json"
require "net/http"
require "openssl"
require "timeout"
require "uri"

module Typesafe
  ENDPOINT = URI("https://api.typesafe.ai/v1/systemone")
  REDACTED = "Bearer [REDACTED]"

  # One call's outcome. `outcome` is always a member of the closed set.
  # Every member is declared here, in Phase 2, so Phase 3 only fills
  # fields and never reshapes the Struct. Serialize with
  # `result.to_h.to_json` (a bare Struct#to_json without json/add/struct
  # is its to_s string).
  Result = Struct.new(:outcome, :reason, :answers, :served_model, :usage,
                      :http_status, :retry_after, :elapsed_ms,
                      :call_id, :site, :mode, :cost_usd, :cost_estimated,
                      :threshold_key, :warnings, :request, keyword_init: true)

  class Client
    def initialize(key:, model:, deadline_ms:, http_class: Net::HTTP,
                   clock: -> { Process.clock_gettime(Process::CLOCK_MONOTONIC) })
    def body(input)            # {"state", "model" => pinned, "questions"}
    def redacted_request(input) # {method, url, headers (Authorization redacted), body}
    def post(input)            # -> Result; exactly one Net::HTTP.start
  end
end
```

Details the implementer must hold to:

- `post` calls `@http_class.start(host, port, use_ssl: true,
  open_timeout: s, read_timeout: s, write_timeout: s) { |http|
  http.request(req) }` exactly once, inside
  `Timeout.timeout(deadline_s)`, where `s = deadline_ms / 1000.0`. The
  block form closes the connection when it exits, including on an
  exception - never hold a `Net::HTTP` instance across calls.
- Rescue order: `Net::OpenTimeout`, `Net::ReadTimeout`, `Net::WriteTimeout`,
  `Timeout::Error` -> `timeout`; then `SocketError`, `SystemCallError`
  (covers ECONNREFUSED / ECONNRESET / EHOSTUNREACH / ...),
  `OpenSSL::SSL::SSLError`, `EOFError`, `IOError`, `Net::HTTPBadResponse`,
  `Net::ProtocolError`, and finally any other `StandardError` (a
  `Net::HTTPHeaderSyntaxError`, a `Zlib::Error` from a compressed body,
  anything unforeseen) -> `transport`. `post` therefore never raises for
  a failed attempt; the only exception it raises is `ArgumentError` for a
  nil key, before any start. `reason` is the exception CLASS name only - never its
  message (a message can quote a URL or a header) and never the response
  body (a body can echo the request's state).
- Status mapping from `response.code`: `200` -> decode; `401`/`403` ->
  `unauthorized`; `422` -> `rejected`; `429` -> `rate_limited` with
  `retry_after` = the `Retry-After` header stripped and capped at 64
  chars when sent, else nil; `529` -> `overloaded`; anything else ->
  `other_status`. `http_status` is the integer code.
- Decode (200 only): `JSON.parse` failure, a non-object body, or
  `answers` missing or not an object -> `undecodable`. Response `model`
  != the pinned model (including absent) -> `model_mismatch` with
  `served_model` set and `answers` nil (discarded, never returned). Else
  `ok` with `answers`, `served_model`, and `usage` =
  `{input_tokens, output_tokens}` (integers or nil when absent). `usage`
  is parsed from any JSON-object body that carries it, whatever the
  outcome, so Phase 3 can price a `model_mismatch` from real tokens.
- `elapsed_ms` from a monotonic clock
  (`Process.clock_gettime(Process::CLOCK_MONOTONIC)` - a read, not process
  creation, so `contract_test.rb`'s process-creation rule does not fire),
  measured around the attempt, set on every Result.
- Request headers: `Authorization: Bearer <key>`,
  `Content-Type: application/json`, `Accept: application/json`. No other
  header carries anything derived from the key.
- `redacted_request` builds the same method/url/headers/body as `post`
  with `Authorization` replaced by `REDACTED`. `inspect` and `to_s` on
  `Client` are overridden to omit the key.
- The pinned model string comes in from the caller; the Client never
  defaults to a `-latest` id and never sends one.

#### 2. A fake `Net::HTTP`
**File**: `skills/wurk:kit/scripts/test/support/fake_http.rb` (new)
**Changes**: `require_relative "home_guard"`. `FakeHTTP` exposes
`start(host, port, **opts) { |conn| ... }` like `Net::HTTP.start`,
records each start (host, port, opts, the request object) in `calls`,
yields a connection whose `request(req)` replays one scripted step:
`respond(code, body:, headers: {})` (builds a real response via
`Net::HTTPResponse::CODE_TO_OBJ` or `Net::HTTPServerError` for 529, sets
the body and read flag, sets headers with `[]=`), `raise_error(exc)`, or
`hang(seconds)` (sleeps, to prove the overall deadline). A `start` with
no scripted step raises `FakeHTTP::Unscripted`.

The fake only protects a caller that injects it, and the library's
default `http_class` is the real `Net::HTTP`. So loading `fake_http.rb`
also installs a process-wide network lock: it prepends a module onto
`Net::HTTP.singleton_class` whose `start` raises
`FakeHTTP::RealNetworkForbidden`. Once any typesafe test file is loaded
(and `run.rb` loads them all), no code path in the test process can open
an HTTP connection, whether or not a test remembered the seam; the

## Phase 3: Gating, budget, privacy and the logs

### Overview

The entry points call sites use: `Typesafe.judge` (one gated call) and
`Typesafe.record_outcome` (the caller's second line), plus
`Typesafe.site_mode` and `Typesafe.threshold_key`. Every refusal the notes
say is checked BEFORE the call is checked here, in a fixed order, and
proven to make no request.

### Changes Required:

#### 1. Policy layer
**File**: `skills/wurk:kit/scripts/lib/typesafe.rb`
**Changes**:

```ruby
module Typesafe
  OUTCOMES = %w[ok site_off source_restricted input_invalid key_missing
                budget_exhausted rate_limited_local unauthorized rejected
                rate_limited overloaded other_status timeout transport
                undecodable model_mismatch].freeze
  NEEDS_NONE = %w[site_off source_restricted rate_limited_local rate_limited
                  overloaded other_status timeout transport undecodable].freeze
  QUESTION_TYPES = %w[choice noul score].freeze
  LEDGER = "ledger-%<month>s.jsonl"       # month = UTC "YYYY-MM"
  DECISIONS = "decisions-%<month>s.jsonl"

  def self.site_mode(config, site)           # "off" | "shadow" | "on"
  def self.threshold_key(site:, question_set:, model:)
    # => "#{site}:#{question_set['id']}@#{question_set['version']}:#{model}"
  def self.validate_input(input, site:)      # -> nil or reason string
  def self.judge(config:, input:, site: nil, dry_run: false,
                 now: Time.now.utc, http_class: Net::HTTP) # -> Result (+ call_id, site, mode, cost_usd, threshold_key, request when dry_run)
  def self.record_outcome(config:, call_id:, site:, action:,
                          decision: nil, agreement: nil, now: Time.now.utc)
end
```

`Result` is the Struct Phase 2 declared with every member already (this
phase fills `call_id`, `site`, `mode`, `cost_usd`, `threshold_key`,
`warnings` and `request`; it does not change the Struct). `call_id` is
`SecureRandom.hex(8)`.

`judge`'s order, each step returning immediately on refusal. Every check
that does not need the key runs before the key file is touched:

1. **Mode.** `site` given: `mode = config.typesafe_site(site)["mode"]`;
   `off` -> `site_off` (no key read, no ledger read, no log line, no
   request - the hot path for every dark site). `site` nil is an ad-hoc
   probe call: mode is reported as `probe`, no site gating, logged with
   `site: null`.
2. **Input.** `validate_input` -> `input_invalid` with a reason naming the
   field (never quoting its value): `state` present (string, object or
   array); `questions` a non-empty object whose ids match
   `UserConfig::TYPESAFE_NAME` and whose entries have `type` in
   `QUESTION_TYPES` and non-blank `instructions`; `criteria` optional (the
   API validates it; a bad one comes back as `rejected`);
   `question_set` = `{id matching TYPESAFE_NAME, version a positive
   integer}` REQUIRED for a site call (the threshold key needs it),
   optional for a probe; `source` optional non-blank string.
3. **Privacy.** `input["source"]` listed in
   `config.typesafe_restricted_sources` -> `source_restricted` in every
   mode, shadow included. An absent `source` is unlabelled and allowed:
   the switch is a deny-list of labels a caller attaches to text from a
   restricted origin, and every call site in scope for this epic passes
   the label for such text (documented as a caller rule in REFERENCE.md).
4. **Budget** (`budget_exhausted`, each with its reason):
   `config.typesafe_monthly_usd` nil -> `budget_unset`; the pinned
   model's `metrics.prices` row missing, or missing `input` or `output`
   -> `price_unknown` (unknown price is could-not-measure, never free);
   any line in this month's ledger with `cost_usd: null`, or any
   malformed line -> `spend_unmeasurable`; `spent + call_bound >
   monthly_usd` -> `cap_reached`, where `spent` sums this month's
   `cost_usd` and `call_bound` is step 8's no-usage bound for this
   request. ASSUMPTION, stated in REFERENCE.md: a token count never
   exceeds the request's byte count; true of common tokenizers,
   unverified for Jev's.
5. **Local rate.** Ledger lines with `ts` in the trailing 60s (reading
   the previous month's file too when `now` is in the first minute of a
   month) `>= config.typesafe_per_minute` -> `rate_limited_local`.
6. **Key.** `config.typesafe_key_path`: not a readable file, or blank
   after strip -> `key_missing` (reason `absent`, `unreadable` or
   `blank`). Group- or world-readable (mode & 077 != 0) adds a
   `key_mode_open` entry to `Result#warnings`, never a refusal. The key
   is read here and only here, held in a local, and passed to
   `Client.new`. Dry run: only existence is checked (`File.file?`, a
   stat) and the file is NOT opened, so a dry run reports `key_missing`
   only for an absent file; an unreadable or blank key surfaces on the
   first live call. The dry run builds `Client.new(key: nil, ...)`:
   `redacted_request` never needs the key, and `post` raises
   `ArgumentError` on a nil key so a dry-run client can never send.
7. **Call.** Dry run: return an `ok`-shaped Result with `request =
   client.redacted_request(input)` and no answers; nothing written.
   Live: `Client#post`, one attempt.
8. **Cost.** When the response reported usage (any outcome):
   `in * input_price / 1e6 + out * output_price / 1e6`. When it did not
   (every non-200, `timeout`, `transport`, and a 200 without usage), the
   provider may still have billed, so the ledger records a conservative
   upper bound with `cost_estimated: true`:
   `request_body_bytesize * input_price / 1e6 +
   OUTPUT_TOKENS_PER_QUESTION_BOUND * question_count * output_price / 1e6`,
   with `OUTPUT_TOKENS_PER_QUESTION_BOUND = 256` (a Jev answer is a small
   typed object; the bound is generous and is an open question). Every
   attempted call therefore gets a NUMBER, so an ordinary timeout never
   turns the month unmeasurable. `cost_usd: null` is never written by
   this code; `spend_unmeasurable` is reached only by a ledger line that
   is malformed or was written null by hand or by a future writer, and
   stays a refusal because an unreadable spend is could-not-measure,
   never free. The cap check in step 4 counts the output bound too, so a
   single call cannot push spend over the cap by more than the bound's
   error; concurrent callers can (see the concurrency note below).
9. **Ledger.** For every attempted call (live only), append one line
   `{ts, month, call_id, site, model, outcome, cost_usd, cost_estimated,
   input_tokens, output_tokens}` to `ledger-<month>.jsonl`, in an
   `ensure`, so an exception mid-attempt still spends a ledger line. The
   client maps every `StandardError` to an outcome (Phase 2), so the
   `ensure` always has one; if anything in `judge` itself raises after
   the attempt, the line is written with `outcome: "transport"` and
   `reason` = the exception class, and `judge` returns that Result
   rather than raising.
10. **Decision log.** For every outcome except `site_off`, append one
    line to `decisions-<month>.jsonl`: `{kind: "decision", ts, call_id,
    site, mode, question_set: {id, version} or null, threshold_key,
    model: pinned, served_model, outcome, reason, http_status,
    retry_after, answers (id -> answer object, as returned) or null,
    input_tokens, output_tokens, cost_usd, latency_ms}`. `state`,
    `questions` (instructions and criteria) and `source` are included
    ONLY when `config.typesafe_log_state?` is true. Dry run writes
    nothing.

`record_outcome` appends `{kind: "outcome", ts, call_id, site, action,
decision, agreement}` to the same decision file. `action` and `decision`
must match `/\A[A-Za-z0-9_.:-]{1,64}\z/` - labels, never prose, so
caller text cannot enter the log by this route; `agreement` is one of
`agree`, `disagree`, `n/a` or nil. Shadow agreement lives here, on the
caller's line, not on the decision line. Invalid values raise
`ArgumentError` (a programming error in the caller; the CLI maps it to
exit 2).

File handling: `FileUtils.mkdir_p(state_dir, mode: 0o700)`; every append
is `File.open(path, File::WRONLY | File::APPEND | File::CREAT, 0o600)`
with ONE `write` of one JSON line ending in `\n`, so concurrent appenders
never interleave inside a line. Reads skip malformed lines (and count
them into a `ledger_malformed` warning) rather than failing: a malformed
ledger line is treated as `cost_usd: null`, i.e. unmeasurable, never as
free. Concurrency across processes is not locked; a race can let two
callers each pass a check that only one should, bounded by one call per
racer - documented, accepted.

  tmpdir in setup and restored in teardown; every config fixture names a
  tmp `state_dir` and a tmp `key_path`; the key file holds a sentinel
  string, never a real key; `FakeHTTP` raises on any unscripted start,
  and loading `fake_http.rb` prepends a lock onto `Net::HTTP.start` that
  raises for the rest of the test process, so a test that forgets the
  seam gets a loud `transport` / `RealNetworkForbidden` instead of a
  connection; no fixture file under `test/fixtures/`
  holds a key or real state text.
- Every new test carries a `# sabotage:` note naming the code change that
  turns it red, in the style of `hooks_test.rb` and `home_guard_test.rb`.

## Decisions

Taken in this plan, beyond the dispatched design:

- The default state dir follows the existing hook convention,
  `${XDG_STATE_HOME:-$HOME/.local/state}/wurk/typesafe`.
- `per_minute` defaults to 60 when absent; `monthly_usd` has no default
  and its absence refuses every live call (`budget_unset`). Dollars must
  be explicit; a request cap has a safe default.
- The pinned model's price row must quote both `input` and `output`;
  otherwise `price_unknown`.
- An attempt whose response reports no usage (timeouts, transport
  failures, most non-200s) is charged a conservative upper bound, never
  zero and never null: the provider may have billed it, and a null would
  make every later call refuse `spend_unmeasurable` until a human
  intervened - one slow response would turn every site off for the month.
  `spend_unmeasurable` stays for a ledger that cannot be read as numbers.
- Budget, rate and every other key-free check run before the key file is
  touched.
- `Result` is declared whole in Phase 2 so Phase 3 never reshapes it.
- Tests hold a process-wide `Net::HTTP.start` lock, not only an injected
  fake.
- `site_off` is not logged (it is every dark site's hot path); every other
  outcome is.
- A site call requires `question_set`; a probe call does not.
- `source` is optional; absent means unlabelled and allowed.
- `input_invalid` is an envelope block (exit 1), not a usage error: it is
  data the caller supplied, and a caller program routes on an envelope.
  Missing flags remain exit 2.
- Two test files (`typesafe_test.rb` for the library,
  `typesafe_cli_test.rb` for the CLI), after the `outbound_scan` pair.

## Open Questions

Non-blocking; each has the default this plan takes, so implementation can
proceed without an answer.

1. Is a new `needs` value (`"none"`) acceptable in `blocked` entries? No
   script uses anything but `"human"` today. Default: yes, for the
   transient outcomes, so a sweep that escalates every `needs: "human"`
   block does not page a person for a 529. If rejected, fall back to
   `"human"` everywhere and let callers route on `data.outcome`.
2. Validating the `typesafe` section at config load means an unknown site
   mode or a `-latest` model blocks EVERY kit script that calls
   `UserConfig.require!` (lock, gate_run, tmux_window...), not only the
   client - the same blast radius a malformed `metrics.prices` has today.
   Default: block at load, as dispatched and as `metrics` does. The
   alternative is to validate the section lazily in `lib/typesafe.rb`, as
   `outbound_scan` defers completeness to scan time.
3. The dispatch sketched a per-site `question_set` config value. Default:
   dropped; the question set's id and version travel in the input beside
   its text. If a site bead needs to pin the version it expects from
   config, add the key then (the site map warns on unknown entry keys, so
   adding one is cheap).
4. Should `restricted_sources` also block when `source` is absent for a
   site the operator marks as "must label"? Default: no; absent is
   unlabelled and allowed, and the REFERENCE.md caller rules require
   sites that may carry restricted text to label it.
5. `typesafe.rb` is the first kit script that talks to the network, and
   `judge_test.rb` pins `judge.rb` away from `Net::HTTP`. Default: no ADR;
   ADR-0006 governs shell-outs and stdlib, and `net/http` is stdlib with
   no shell-out. Worth an ADR if a second networked script appears.
6. The no-usage cost bound uses `OUTPUT_TOKENS_PER_QUESTION_BOUND =
   256` and assumes tokens never exceed request bytes; neither is
   documented by the provider. Default: keep both, stated in REFERENCE.md,
   and revisit once the ledger has real usage numbers to compare with.
7. `HomeGuard` does not pin `XDG_STATE_HOME`. Default: the typesafe tests
   pin it themselves and `home_guard.rb` is not edited here; a follow-up
   bead could move that into the guard for every future state-writing
   test.
